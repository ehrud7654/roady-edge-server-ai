# 서버 AI 연결 현황

Jira: `S15P11A404-168`

## 현재 배포 모델

| 항목 | 값 |
|---|---|
| 모델 | YOLO26s-seg |
| 가중치 | `models/server/yolo26s_seg_multiclass_v4_best.pt` |
| 입력 | Edge가 전송한 점자블록 기준 ROI |
| 입력 크기 | 768 |
| 결과 정책 | 잠정 정책(`draft-1`), `advisory_only=true` |

## 모델 클래스와 서비스 표시

| ID | 학습 클래스 | 서비스 결과 | 처리 방식 |
|---:|---|---|---|
| 0 | `tactile_block` | 점자블록 | 파손 비율 계산의 기준 영역 |
| 1 | `missing` | 큰 결손·작은 결손 | 비율을 신뢰할 수 있을 때 15% 기준으로 후처리 구분 |
| 2 | `crack` | 균열 | 점자블록 내부의 유효 균열 Mask 분석 |
| 3 | `wear` | 마모 | 점자블록 내부의 유효 마모 Mask 분석 |
| 4 | `obstruction` | 거치물 | 파손 분석을 확정하지 않고 `OBSTRUCTION_SUSPECTED` 판단 보류 |

## v3 고정 Test 결과(롤백 비교 기준)

고정 Test 45장, 249개 인스턴스를 `imgsz=1024`로 평가한 결과입니다.

| 클래스 | Mask Precision | Mask Recall | Mask mAP50 | Mask mAP50-95 |
|---|---:|---:|---:|---:|
| `tactile_block` | 0.962 | 0.958 | 0.988 | 0.916 |
| `missing` | 0.971 | 0.800 | 0.868 | 0.789 |
| `crack` | 0.521 | 0.583 | 0.409 | 0.081 |
| `wear` | 0.918 | 0.757 | 0.909 | 0.459 |
| `obstruction` | 0.747 | 0.750 | 0.912 | 0.801 |

`obstruction_confidence=0.25` 기준 클래스 존재 판정은 거치물 이미지 4/4를 탐지했고,
비거치물 이미지 41장에서는 거치물 오탐이 없었습니다. 표본이 작으므로 자동 행정 판정에
사용하지 않고 `review_required=true`, `advisory_only=true` 판단 보류 정책을 유지합니다.

## v4 후보 선택 결과

점자블록 개별 인스턴스 분리와 작은 결손 복원을 강화한 v4를 동일 후보 선택 평가로 비교했습니다.
종합 선택 점수는 `0.7299`로 v3의 `0.6746`보다 높았고, 작은 결손 부분집합 Mask Recall은
`0.750`이었습니다.

| 클래스 | Mask Recall | Mask AP50 |
|---|---:|---:|
| `tactile_block` | 0.831 | 0.813 |
| `missing` | 0.735 | 0.967 |
| `crack` | 0.667 | 0.607 |
| `wear` | 0.782 | 0.938 |
| `obstruction` | 1.000 | 0.995 |

전체 Mask mAP50-95는 `0.606`입니다. 이 수치는 후보 선택용 평가 결과이며, 독립 로봇 주행 영상의
종단 간 검증을 대체하지 않습니다. 따라서 자동 보수 권고는 활성화하지 않고
`review_required`, `advisory_only` 안전 정책을 유지합니다.

큰 결손과 작은 결손은 별도 학습 클래스가 아닙니다. 모델은 두 유형을 `missing`으로 분할하고,
개별 점자블록 대비 결손 비율을 계산할 수 있을 때만 15% 기준으로 구분합니다. 예상 블록 영역을
신뢰할 수 없으면 비율은 `null`로 유지하되 `LARGE_MISSING`, 보통 심각도를 적용합니다.
점수는 점자블록 검출 여부나 비율과 무관하게 통합 파손 마스크 픽셀 수로 계산합니다.

## 판단 보류

다음 조건에서는 판정값을 반환하면서 결과를 담당자 검토 대상으로 표시합니다.

- 점자블록을 찾지 못한 경우
- 개별 블록 분리가 불가능해 블록 그룹 단위로 분석한 경우
- 결손 비율 계산에 필요한 예상 블록 영역을 만들 수 없는 경우
- 점자블록 또는 파손 신뢰도가 기준보다 낮은 경우
- 파손 비율이 심각도 등급 경계에 가까운 경우
- 대표 프레임 품질이 검증되지 않은 경우
- Edge가 파손 후보 fallback ROI를 사용한 경우
- 모델 클래스 구성이 4클래스 계약과 다른 경우
- Edge에서는 파손 후보가 탐지됐지만 서버가 `missing`, `crack`, `wear`를 확정하지 못한 경우

계산할 수 없는 비율은 `0`으로 바꾸지 않고 `null`, `ratio_status=not_estimable`로 반환하지만,
탐지된 결손 자체는 보수적 기본값으로 파손 판정을 완료합니다.
현재 모든 분석 결과는 확정 행정 판단이 아닌 권고 결과이며 `advisory_only=true`입니다.
모델 전체 검증 지표인 `quality`는 참고 정보로만 제공하며 이미지별 판정과 검토 여부에는 사용하지 않습니다.

## 씽씽이 등 가림 물체 처리

씽씽이는 Edge에서 `damage_candidate`로 서버에 전달되며 서버의 `obstruction` 클래스로 분석합니다.
거치물이 검출되면 파손 유무나 비율을 임의 확정하지 않고 `OBSTRUCTION_SUSPECTED`,
`review_required=true`로 담당자 판단 보류에 연결합니다.

## API 연결

- `POST /analyze`: 원본 이미지, 분석 ROI 및 Edge 메타데이터 분석
- `GET /health/live`: 프로세스 생존 확인
- `GET /health/ready`: 모델 로딩·워밍업 완료 확인
- `GET /model-info`: 모델 파일명, SHA-256 및 클래스 매핑 확인

주요 응답 필드는 `units`, `summary`, `review_required`, `review_reasons`, `advisory_only`,
`artifacts`입니다. 기존 `regions.damage`와 최상위 `analysis` 필드는 백엔드 하위 호환을 위해
deprecated 상태로 유지합니다.
